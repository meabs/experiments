We’ve reached a consistent design:

- Add `PUT /api/support/cases/{caseId}/assignee`.
- Require authentication plus `accounts:write`.
- Permit tenant admins for any case in their tenant; permit support users only when the case is currently assigned to them. Customers and other roles get 403; invisible/missing cases are 404.
- `assigneeUserId` must be a nonblank existing support identity who is assigned to that case’s account in the same tenant. Any failure there is 400, with no mutation.
- Unassigned cases are admin-only to reassign.
- Reassignment is allowed in every case status and is idempotent.
- Return HTTP 200 with exactly `id`, `accountId`, `subject`, `status`, `assigneeUserId`, and `openedAt`.
- Use one transaction, no audit/notification side effects, and existing lenient handling of unknown JSON fields.
