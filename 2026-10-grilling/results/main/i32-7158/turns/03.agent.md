The design is settled: exact `LocalDate` values, inclusive bounds, blank/repeated/alternate formats rejected, equal dates allowed, empty results unchanged, and invalid ranges rejected before account access/query. I’m implementing that while preserving ordering, scope, and visibility behavior.

Implemented date-range filtering for `GET /api/accounts/{accountId}/transactions`.

- Added optional inclusive `from` and `to` ISO date parameters.
- Rejects blank, repeated, malformed dates, and reversed ranges with 400.
- Preserves ordering, response fields, access checks, scope requirements, and empty-list behavior.
- Added repository queries for lower-bound, upper-bound, and bounded filtering.
