The design is settled: I’ll add the staff/admin-only POST endpoint, enforce assigned-support vs tenant-admin access, restrict support to internal notes, trim and validate the body, preserve standard 400/403/404 behavior, and leave existing read behavior untouched.

Implemented `POST /api/accounts/{accountId}/notes`.

Behavior includes:

- Support/admin authorization with existing `accounts:write` scope.
- Assigned-support and same-tenant-admin access rules.
- Support users restricted to `internal: true`; public notes return 403.
- Strict validation and trimming of `body` (1–2000 characters).
- Strict boolean validation for `internal`.
- Caller ID as author and server-generated `createdAt`.
- 201 response with the requested note fields.
- Standard 400/403/404 handling preserved.

Verified with `mvn -o -q test` — all tests pass.
