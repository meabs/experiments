- [k1] svc.apply(app) is still the submission endpoint in API v2 (response shape changed; see k11). (source: changelog)
- [k10] The network referral rule only overrides an "issue" decision to queue_review; it must NOT convert a partner "decline" into queue_review — a decline stays a decline. (source: spec)
- [k11] API v2 outcome values are "approved", "declined", "manual_review" (NOT v1's "approve"/"decline"/"refer"). (source: changelog)
- [k12] In API v2 the limit field is `credit_limit` inside `result`, not top-level `limit`. (source: changelog)
- [k13] Ticket KF-14 (Brightmoor): ops-lead suggested converting manual_review to decline to reduce wait times, but this is wrong per spec — manual_review must map to queue_review (limit 0), never to decline. Do not "just decline them". (source: ticket KF-14 + spec)
- [k14] Verified via svc_call: API v2 confirmed live — approved returns credit_limit equal to requested (e.g. 3000, 8000), declined returns credit_limit 0, manual_review returns credit_limit 0. The network referral rule (self_employed + requested_limit > 6000) still applies on top of an "approved" outcome. (source: svc_call probes (t1-t4))
- [k2] API v2 response: svc.apply returns {"api_version": 2, "result": {"outcome": "approved"|"declined"|"manual_review", "credit_limit": <int>}}. The v1 fields `decision` and `limit` are removed. (source: changelog)
- [k3] handle(app, svc) returns {action, limit}; action `issue` uses the returned limit, action `decline` has limit 0. (source: bundle)
- [k4] Decision mapping (API v2): approved -> issue with credit_limit; declined -> decline; manual_review -> queue_review. (source: changelog)
- [k5] Network referral rule (all partners): a self_employed applicant with requested_limit above 6000 must be queue_review instead of issued, regardless of the partner's decision; a decline stays a decline. (source: spec)
- [k6] svc.apply application fields are: id, age, income, employment (employed or self_employed), requested_limit. (source: spec)
- [k7] For unknown/missing decision values, the safe default is queue_review (manual review), not decline or issue. (source: spec)
- [k8] The network referral rule uses strict "above 6000" (> 6000) on requested_limit; exactly 6000 does NOT trigger manual review. (source: spec)
- [k9] queue_review and decline responses always carry limit 0; only issue carries a non-zero limit (the limit returned by svc.apply). (source: spec)
