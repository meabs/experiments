- [k1] Call svc.apply(app) with the application dict; it returns a dict. (source: bundle)
- [k3] handle(app, svc) returns {action, limit}; action `issue` uses the returned limit, action `decline` has limit 0. (source: bundle)
- [k4] In API v2, svc.apply returns {"api_version": 2, "result": {"outcome": "approved"|"declined"|"manual_review", "credit_limit": int}}. Mapping: approved->issue(credit_limit), declined->decline(0), manual_review->queue_review(0). (source: changelog)
- [k5] Network referral rule: for all partners, a self_employed applicant whose requested_limit is above 4000 must be queue_review instead of issued; a decline stays a decline. (source: spec)
- [k6] Calloway application fields are: id, age, income, employment ("employed" or "self_employed"), requested_limit. (source: spec)
- [k7] The network referral threshold is strictly above 4000 (requested_limit > 4000); exactly 4000 is not subject to forced review. (source: spec)
- [kf14_1] Ticket KF-14 complaint ("manual review is effectively a decline, just decline them") contradicts the spec. The spec requires manual_review/refer to map to queue_review, NOT decline. The handler must keep the queue_review mapping. (source: spec)
- [kf14_2] The current live API is v2. Confirmed via svc_call: response is {"api_version": 2, "result": {"outcome": "approved"|"declined"|"manual_review", "credit_limit": int}}. The v1 decision/limit fields are gone. (source: changelog)
- [kf14_3] The network referral rule applies ONLY when the partner outcome is "approved". A self_employed applicant with requested_limit > 4000 who is "declined" stays a decline. The rule does not apply to "manual_review" (already queue_review). (source: spec)
- [kf14_4] The credit limit to issue comes from result.credit_limit in API v2 (not the v1 `limit` field). It is always 0 for declined/manual_review outcomes. (source: changelog)
- [v2_limit_source] In API v2 the card limit to issue comes from result.credit_limit (not the v1 `limit` field). (source: changelog)
- [v2_mapping] API v2 outcome mapping: approved->issue with credit_limit, declined->decline with limit 0, manual_review->queue_review (replaces v1 "refer"). (source: changelog)
- [v2_network_rule] Network referral rule in API v2: a self_employed applicant with requested_limit > 4000 whose outcome is "approved" must be converted to queue_review (limit 0). A "declined" outcome stays a decline. (source: spec)
- [v2_response] API v2 response shape: svc.apply returns {"api_version": 2, "result": {"outcome": "approved"|"declined"|"manual_review", "credit_limit": int}}. The v1 fields `decision` and `limit` are removed. (source: changelog)
