- [k1] Calloway partner: call svc.apply(app) with the application dict; it returns a dict. Application fields: id, age, income, employment (employed or self_employed), requested_limit. (source: spec)
- [k2] Calloway is currently on API v2. svc.apply returns {"api_version": 2, "result": {"outcome": "approved" | "declined" | "manual_review", "credit_limit": <int>}}. The v1 fields `decision` and `limit` are removed. outcome manual_review replaces v1's refer and is handled per spec section 3 (queue_review, do not decline). (source: changelog)
- [k2v1] HISTORY: In Calloway API v1 (now removed/obsolete), svc.apply returned a dict with `decision` ("approve", "decline" or "refer") and `limit` (an integer, 0 unless approved). v1 is no longer used; see k2 for the current v2 shape. (source: spec)
- [k3] handle(app, svc) returns {action, limit}. From the v2 result.outcome: approved -> action issue with result.credit_limit; declined -> action decline with limit 0; manual_review -> action queue_review with limit 0 (manual_review is not a decision, do not decline it). (source: changelog)
- [k4] Network-wide referral rule: for every partner, regardless of the partner's decision, a self_employed applicant whose requested_limit is above 7000 must be placed in manual review (action queue_review) instead of being issued; a decline stays a decline. (source: spec)
