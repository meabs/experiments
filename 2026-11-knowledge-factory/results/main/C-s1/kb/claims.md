- [k1] Call svc.apply(app) with the application dict; it returns a dict. (source: bundle)
- [k2] In API v2 (current) svc.apply returns {"api_version": 2, "result": {"outcome": "approved"|"declined"|"manual_review", "credit_limit": <int>}}. The v1 fields `decision` and `limit` are removed. (source: changelog)
- [k3] handle(app, svc) returns {action, limit}. Read the v2 response: outcome = resp["result"]["outcome"], credit_limit = resp["result"]["credit_limit"]. If outcome is "approved" -> action "issue" with the returned credit_limit; "declined" -> action "decline" with limit 0; "manual_review" (replaces v1 "refer") -> action "queue_review" with limit 0 (do not decline). (source: changelog)
- [k4] Network referral rule (spec section 4, applies to all partners including Brightmoor): whatever the partner decided, an application from a self_employed applicant whose requested_limit is above 6000 must be placed in manual review (action queue_review) instead of being issued. A decline (v2 outcome "declined") stays a decline (action decline, limit 0). (source: spec)
- [k5] svc.apply(app) returns a dict with api_version 2 and a `result` object containing `outcome` ("approved", "declined" or "manual_review") and `credit_limit` (an integer, 0 unless approved). The v1 fields `decision` and `limit` no longer exist. (source: changelog)
