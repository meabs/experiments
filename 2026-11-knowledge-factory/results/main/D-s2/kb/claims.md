- [k1] Call svc.apply(app) to submit an application; it returns a dict. Application fields are id, age, income, employment (employed or self_employed), requested_limit. (source: spec)
- [k2] API v2 is current. svc.apply returns {"api_version": 2, "result": {"outcome": "approved" | "declined" | "manual_review", "credit_limit": <int>}}. The v1 fields `decision` and `limit` are removed. (source: changelog)
- [k3] handle(app, svc) returns {action, limit}. In API v2, outcome `approved` maps to action `issue` using result.credit_limit; `declined` maps to action `decline` with limit 0; `manual_review` (replaces v1 `refer`) maps to action `queue_review` with limit 0 — the spec explicitly says the application "is not decided" and "do not decline it", so manual review must never be turned into a decline (e.g. ticket KF-14's ops-lead instruction to decline manual-review applicants contradicts the spec and must not be followed). (source: spec)
- [k4] Network referral rule (all partners): whatever the partner decided, an application from a self_employed applicant whose requested_limit is above 6000 (strictly > 6000; 6000 itself does not trigger it) must be placed in manual review (queue_review) instead of being issued; a decline stays a decline. (source: spec)
