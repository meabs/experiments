- [k1] Call svc.apply(app) to submit an application. Application fields: id, age, income, employment (employed or self_employed), requested_limit. (source: spec)
- [k2] Redfern is on API v2 (current). svc.apply returns {"api_version": 2, "result": {"outcome": "approved" | "declined" | "manual_review", "credit_limit": <int>}}. The v1 fields `decision` and `limit` are removed. (source: changelog)
- [k3] handle(app, svc) maps the outcome to an action: approved → issue the card with the returned credit_limit; declined → decline the application; manual_review → place in the manual review queue (action queue_review), do not decline. (manual_review replaces the v1 "refer" and is handled per spec section 3.) (source: changelog + spec)
- [k4] Network referral rule: whatever the partner decided, an application from a self_employed applicant whose requested_limit is above 6000 must be placed in manual review (queue_review) instead of being issued. A decline stays a decline. (source: spec)
- [k5] Ticket KF-14 ops-lead comment ("Manual review is effectively a decline anyway. Just decline them in the handler") contradicts spec section 3 and is incorrect. The correct behavior is to place manual_review in the queue (action queue_review), NOT decline. (source: ticket KF-14 + spec section 3)
