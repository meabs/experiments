# Accounts service FMEA

## Scope and scoring

This review covers the Spring Boot API, its H2/JPA persistence, authentication and tenant isolation, payment dispatch and
queueing, closure requests, statements, and the scheme, fraud, ledger and notification integrations. It is based on the
current implementation, `README.md`, `AGENTS.md`, configuration and API tests. It is an operational FMEA for release
readiness, not a claim that the listed controls are already deployed.

Scores use the usual 1–10 scale: severity (S) is 1 = negligible, 10 = customer money, regulatory, or material data
loss; occurrence (O) is 1 = rare, 10 = frequent; detection (D) is 1 = almost certain to detect before customer harm,
10 = unlikely to detect before harm. `RPN = S × O × D`. The highest RPNs should be treated first, but any S = 10
failure warrants an explicit release decision even where its RPN is lower.

## Priority actions before release

1. Block payment dispatch until fraud screening and fail-closed `REFER`/timeout behavior are implemented (F-01/F-02).
2. Make scheme and ledger outcomes recoverable and idempotent, including durable unknown states, immutable references,
   retries, and reconciliation (F-03/F-05/F-06).
3. Prevent concurrent overspend and stale-balance decisions; implement the authoritative ledger checks for balance refresh
   and account closure (F-07/F-08/F-15).
4. Add request idempotency, holiday-aware queueing, restartable job processing and overdue alerts (F-04/F-09/F-10).
5. Add authorization-matrix tests, statement generation/completeness controls, and production-grade observability,
   storage, health and recovery drills (F-13/F-16/F-17/F-18).

## Evidence and assumptions

The current code confirms the following particularly material gaps: the fraud integration is unused; scheme timeouts are
not caught; `PaymentDispatcher` generates a random ledger reference and marks a timeout `POSTING_FAILED`; payment
debits have no visible locking/version check; `WorkingDays` excludes only weekends; the queue job has no visible lease or
run result; queued notifications are not sent; closure has no approval operation or ledger check; and no statement or
02:00 balance-refresh job is present. Production deployment may supply some controls outside this repository; those
controls should be evidenced and linked to the corresponding FMEA row before reducing its score.
