# Accounts service FMEA

## Scope and method

This review covers the customer and staff API, persistence, scheduled queue processing, security boundaries, and the
scheme, fraud, ledger and notification integrations. It is based on the current implementation and the operational
constraints in `README.md` and `AGENTS.md`, including the fact that the account balance is a copy of the ledger.

Scores use the conventional 1–10 scale:

- **Severity (S):** 1 = negligible inconvenience; 10 = customer funds lost/double-paid, material data breach, or a
  regulatory/availability failure.
- **Occurrence (O):** 1 = exceptional; 10 = expected frequently or on the normal path.
- **Detection (D):** 1 = almost certain to detect before customer/system impact; 10 = unlikely to detect until a
  customer, reconciliation, complaint, or regulatory process finds it.

RPN is `S × O × D`. The scores are comparative release-prioritisation scores, not probabilities. They assume the
current controls only; proposed actions are not included in the scores.

## Priority and release gates

The highest-priority risks are F-01 (RPN 800), F-05 (504), F-03 (500), F-02/F-04 (450), F-06 (432), F-09 (400), and
F-07 (384). F-01–F-04 and F-09 are release blockers for a payment release because they can violate fraud policy,
lose an externally accepted payment, or create a duplicate debit. F-05/F-06 should be closed before increasing payment
volume. F-07/F-08 require an operationally safe queue before relying on scheduled payments.

At minimum, release evidence should include:

1. Fraud ACCEPT/REFER/REJECT, timeout and error tests, with no scheme call for REFER/REJECT/unavailable.
2. Scheme timeout-after-accept recovery using the original scheme reference, including restart recovery.
3. Ledger timeout-before/after-booking recovery using the same persisted ledger reference, with no duplicate debit.
4. Parallel-payment invariant tests for balance, daily limit and idempotency.
5. Bank-holiday, DST, missed-job and duplicate-worker tests, plus dashboards and alerts for aged `QUEUED`,
   `POSTING_FAILED` and in-flight payments.
6. Tenant/role/scope negative API tests and a notification contract test proving that only the last four account digits
   can leave the service.
