# Accounts service FMEA

Review date: 2026-11-04  
Scope: the Spring Boot API, its scheduled payment job, persistence, security boundary, and the scheme, fraud,
ledger and notification integrations described in `okf/`. This is a current-state assessment for the next release;
the scores include known gaps even where the code has tests around the intended behaviour.

## Scoring

Scores are on a 1–10 scale. Severity (S) measures customer, financial, regulatory or operational harm; occurrence
(O) measures expected frequency or exposure; detection (D) measures how likely the failure is to escape detection
(1 = almost certain to detect promptly, 10 = unlikely to detect before harm). The risk priority number is `S × O × D`.
RPN is a prioritisation aid, not a substitute for treating any S=9–10 control failure. The recommended action is the
first release-appropriate mitigation; monitoring should be added to every action that changes a state or sends money.

## Release priorities

Before release, treat F-01, F-02, F-04, F-05, F-10 and F-11 as release blockers because they can permit fraud or
financial loss, strand funds, or prevent a regulatory obligation from being met. F-03, F-07, F-12 and F-16 should be
closed or have an explicitly accepted risk owner and a tested operational runbook. The remaining items need owners,
alerts and a dated remediation plan.

At minimum, the production dashboard should show payment counts by status and age, unknown scheme outcomes,
`POSTING_FAILED` age/volume, overdue queued payments, fraud-screening coverage, ledger/scheme reconciliation breaks,
notification failures, statement completeness, closure-request age, dependency latency/error rates, and balance-refresh
freshness. Alerts should route to payments operations, fraud, finance reconciliation, regulatory reporting and the
Accounts squad according to the failure mode rather than relying on application logs alone.
