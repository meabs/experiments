The key unresolved branch is the approval workflow for amounts over £100. The repository already defines an `APPROVER` role, but there is no goodwill model or approval endpoint yet, so we need to pin down whether this ticket includes the pending/approval lifecycle or only the straight-through path.

❓ **Q9 — What does POST do for amounts over £100?** The current response contract has no `status`, `approvedBy`, or approval timestamp. Should `POST /goodwill-credits`:

1. **Create a pending credit** and return `201` (requiring us to extend the response with status/approval fields), or
2. **Refuse to create it** until approval exists (which would require a separate approval/request workflow), or
3. **Allow it only when the caller is already an approver**, while ordinary staff get an error?

➡️ Recommended: create a `PENDING` goodwill-credit request for >£100 with `201`, and apply the balance/transaction only on approval. This matches the existing closure-request pattern and avoids silently bypassing the stated control.

---

❓ **Q10 — Approval API scope:** Does this ticket include the approval operation and discovery endpoint (for example `GET /api/goodwill-credits?status=PENDING` and `POST /api/goodwill-credits/{id}/approve`), or should I implement only the specified POST and leave over-£100 approval integration for a later ticket?

➡️ Recommended: include minimal approval endpoints now; otherwise the >£100 path can create records that nobody can action.

---

❓ **Q11 — Who may approve?** Should any tenant user with `APPROVER` approve, or must they also be `ADMIN`/assigned support?

➡️ Recommended: any `APPROVER` in the account’s tenant, regardless of account assignment, because approval is a tenant-wide control and the existing closure pattern scopes approver queues by tenant.

---

❓ **Q12 — Separation of duties:** May the staff member who submitted a >£100 credit approve their own request?

➡️ Recommended: no; require a different approver user id. This is the point of “needs approving before it’s paid.”

---

❓ **Q13 — Pending visibility:** Who can see pending/approved goodwill records?

➡️ Recommended: tenant approvers see pending requests; the submitting/assigned staff can see the created record by id if we add retrieval, while customers see none. Do you want a retrieval/list endpoint in this ticket, or only the approval queue?

---

❓ **Q14 — Approval effects and races:** On approval, should we re-check that the account is still open and then atomically add the balance plus one `Goodwill credit` transaction; and should an already decided request return `409`?

➡️ Recommended: yes to both, with `409` for duplicate/late decisions and `409` if the account closed before approval.
