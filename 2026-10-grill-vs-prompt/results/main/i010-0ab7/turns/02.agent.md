The endpoint is now wired with tenant isolation, `APPROVER` plus write-scope authorization, transactional account closure, timestamps, and 409 handling for decided/closed states. I’m running the offline test suite and will add focused coverage if anything exposes a convention mismatch.

Implemented `POST /api/closure-requests/{requestId}/approve`.

Behavior:

- Requires `APPROVER` role and `accounts:write` scope.
- Enforces tenant isolation.
- Returns `404` for missing/cross-tenant requests.
- Returns `409` for already-decided requests or already-closed accounts.
- Sets request status, approver, and decision timestamp.
- Closes the associated account.
- Returns the closure request view, including `decidedAt`.
