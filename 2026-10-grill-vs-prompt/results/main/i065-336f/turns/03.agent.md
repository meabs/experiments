Agreed design:

- Add `POST /api/accounts/{accountId}/notes`, requiring a bearer token, `accounts:write`, and `SUPPORT` or `ADMIN`.
- Resolve the account through existing visibility rules; invisible or missing means 404.
- Accept only the required `body` and `internal` inputs semantically: body is trimmed, 1–2000 chars; internal must be a JSON boolean. Invalid/missing/null values return 400 without saving.
- Any visible account state is eligible; each valid request appends a new note.
- Populate `author` from the caller’s token subject and `createdAt` from the server clock.
- Return 201 with exactly `id`, `author`, `body`, `internal`, and `createdAt`.
- Preserve existing conventions and behavior, including tenant isolation and staff-only note semantics.
