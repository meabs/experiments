Thanks—those rules settle the authorization and state behavior. I’ll implement the endpoint with the existing visibility semantics, `accounts:write`, admin/support role checks, closed-account conflict handling, and strict whole-pound validation.

Implemented `PUT /api/accounts/{accountId}/daily-limit`.

Behavior:

- Requires `accounts:write`.
- Admins can set any non-negative whole-pound limit within `int` range.
- Assigned support users can set the same or a lower limit.
- Customers and unauthorized staff receive 403.
- Invisible accounts return 404.
- Closed accounts return 409.
- Invalid, missing, fractional, negative, textual, or oversized values return 400.
- Returns the normal `AccountView` shape with HTTP 200.
