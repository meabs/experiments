The design is settled: bank admins may set `0..5000`, assigned support may only strictly lower the current value, customers are denied, and success returns the normal account view. I’m implementing this through the existing authorization, validation, and error conventions now.

Implemented `PUT /api/accounts/{accountId}/daily-limit`.

- Validates `dailyLimit` as a required whole number from `0` through `5000`.
- Requires `accounts:write`.
- Bank admins can set any valid limit.
- Assigned support users can only lower the current limit.
- Customers and unauthorized users are rejected using existing conventions.
- Returns the updated account in the existing `AccountView` shape.
- Uses a database write lock to enforce the support-user lowering rule atomically.
- Malformed request bodies now return the standard 400 error shape.
