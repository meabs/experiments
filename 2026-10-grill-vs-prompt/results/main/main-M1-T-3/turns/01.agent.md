The existing model supports resource-level visibility for assigned support staff and tenant admins, while customers can only view their own accounts. I’ll make the new write endpoint require `accounts:write`, then enforce “assigned support or same-tenant admin” before changing the limit.

The first implementation used `Integer`, but Jackson can coerce some JSON decimals to integers. To guarantee that a value like `750.5` is rejected rather than truncated, I’m tightening the request model to validate the numeric value as a whole, non-negative pound amount within the entity’s integer range.

Implemented `PUT /api/accounts/{accountId}/daily-limit`.

- Requires `accounts:write`.
- Allows assigned support staff and same-tenant admins only.
- Validates missing, negative, fractional, and out-of-range values as `400`.
- Returns the updated account in the existing account view shape.
- Customers cannot change limits.
