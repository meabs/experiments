The design is now fully specified:

- `PUT /api/accounts/{accountId}/daily-limit`
- Requires the existing `accounts:write` scope plus:
  - bank/tenant admins may set any valid limit;
  - assigned support users may set a limit equal to or below the current one;
  - assigned support users raising it get 403;
  - customers and other visible-but-forbidden users get 403;
  - accounts outside the caller’s bank remain indistinguishable and return 404.
- Body must contain a finite, non-negative, whole numeric `dailyLimit` from 0 through 5000 inclusive; missing, fractional, negative, over-ceiling, overflow, wrong type, or malformed values return 400 with no update.
- Success returns 200 and the same `AccountView` shape as GET.
- The normal transactional persistence path is used.
