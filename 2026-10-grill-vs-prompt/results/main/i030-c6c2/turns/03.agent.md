The design is settled: admins can reassign any tenant case, the current assignee can hand it over, eligibility comes from `support_assignments`, failures are non-mutating, and success is `200` with the requested fields. I’m implementing this within the existing security and error-handling conventions now.

Implemented `PUT /api/support/cases/{caseId}/assignee`.

- Admins can reassign cases within their tenant.
- Current assignees can hand cases over.
- Other users receive `404`.
- Target assignees must be assigned to the case’s account; invalid targets return `400`.
- Reassignment is atomic and supports idempotent same-user updates.
- Returns the requested case fields with `200 OK`.

All tests pass with `mvn -o -q test`.
