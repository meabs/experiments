# Experiments

Agent experiments run with [AgentTrialRig](https://github.com/meabs/AgentTrialRig). One folder per experiment. Each folder has a `README.md` holding the design, written before any measured run, and a `results/` folder holding the raw runs and the analysis.

| Folder | Question | Status |
| --- | --- | --- |
| [2026-10-skills-impact](2026-10-skills-impact/) | Do popular agent skill packs (Superpowers, Matt Pocock's skills, pstack) change correctness or cost on a real Java repository? | Done: no pass-rate gain; Superpowers works test-first at 2–3x tokens ([report](2026-10-skills-impact/REPORT.md)) |
| [2026-10-caveman](2026-10-caveman/) | Does the caveman skill cut tokens without losing correctness? | Done (Codex): output down 13%, total saving not shown, correctness held ([report](2026-10-caveman/REPORT.md)) |
| [2026-10-skills-tasks](2026-10-skills-tasks/) | Across 16 different tasks at low effort, do Superpowers or Pocock's skills raise the pass rate? | Done (Codex): no significant gain (Pocock 27/32, Superpowers and control 24/32); Superpowers 3.1x tokens; 28 of 30 failures claimed success ([report](2026-10-skills-tasks/REPORT.md)) |
| [2026-10-verify-vs-skills](2026-10-verify-vs-skills/) | Which buys more correct changes per dollar: a short instruction to verify against the running app, the Superpowers pack, or more reasoning effort? | Done (Codex): only medium effort helped (49/60 vs 36/60, Holm p 0.041); verify 39/60 and Superpowers 37/60 not significant; the app could not start outside its tests, so verify rarely checked it ([report](2026-10-verify-vs-skills/REPORT.md)) |
| [2026-10-repo-skills](2026-10-repo-skills/) | Does repository-specific guidance (an agent-written AGENTS.md and skills) raise the pass rate over no guidance? | Done (Codex): agent-written repo guidance did not measurably help (40/60 vs 38/60, p 0.40), at 1.3x cost per correct change; only 8 of 60 runs opened the verify skill ([report](2026-10-repo-skills/REPORT.md)) |
| [2026-10-explicit-skills](2026-10-explicit-skills/) | Does telling the agent to use the repository skills (not just leaving them to be discovered) raise the pass rate? | Done (Codex): told to use the skills, the agent read them every time (verify-api 60/60 vs 3/60) but mostly ran a smoke test rather than testing its change; 42 and 43 vs 37 of 60, not significant, at about 2x cost per correct change ([report](2026-10-explicit-skills/REPORT.md)) |
| [2026-10-test-skill](2026-10-test-skill/) | Told to write a focused API test, does a verification skill help the agent write one that really checks its change, and does the skill's design matter? | Done: an instruction alone got a real test in 56/60 runs; the skill added nothing; a Stop-hook gate got 58/60; no arm but medium effort raised the pass rate significantly |
| [2026-10-test-skill-local](2026-10-test-skill-local/) | Does test-skill hold with a local open-weight model (qwen3.8:27b, Q4, via Ollama) instead of hosted gpt-5.6-luna, same tasks, arms and grader? | Pilot stopped: every run hit the time limit; not analysed |
| [2026-10-diff-judge](2026-10-diff-judge/) | Shown a task and an agent's change, can a model (gpt-5.6-luna) tell whether it passes the hidden tests, and does the agent's own success report sway it? | Done: barely better than chance (57/96, balanced accuracy 0.59, Holm p 0.14); the agent's report did not sway it; a doubtful report made it reject more of everything; confidence was uninformative ([report](2026-10-diff-judge/REPORT.md)) |
| [2026-10-benchmark-twins](2026-10-benchmark-twins/) | Do models (local qwen3.8:27b, hosted gpt-5.6-luna) score lower on GSM8K and HumanEval items once the numbers, names or function name are changed, a sign of memorisation? | Done: no measurable drop on twins for either model (local GSM8K numbers 168 vs 161 of 184, Holm p 0.46; hosted 175 vs 172); no wrong twin answer repeated the original's ([report](2026-10-benchmark-twins/REPORT.md)) |
| [2026-10-planted-errors](2026-10-planted-errors/) | Does a reasoning model's visible thinking drive its answer? Edit a number in the middle of a local model's (qwen3.8:27b) thinking on GSM8K problems and see whether the answer follows, recovers or changes | Done: the thinking drives the answer (forced answer 23% right with no thinking, 94% after it); a planted wrong number was carried to the matching wrong answer in 81 of 230 runs (35%), nearly always without doubt; 54% caught in the thinking; in 23 runs the thinking ended on the wrong answer and the reply silently fixed it ([report](2026-10-planted-errors/REPORT.md)) |
| [2026-10-evidence-manipulation](2026-10-evidence-manipulation/) | Can manipulated evidence (falsified facts, prompt injection, or both) mislead a local AI security-triage agent (qwen3.8:27b), and does an independent verification tool help? | Done: one falsified fact led to a wrong decision in 81 of 120 runs (68%; 38% even when another record contradicted it), mostly stated with low uncertainty; a blunt injected instruction changed 0 of 120 decisions and was always flagged; with both, it flagged the injection and still believed the false fact (61% wrong); a verification tool fixed 359 of 360 manipulated runs; 10 runs made a stray contrary action call after a correct decision ([report](2026-10-evidence-manipulation/REPORT.md)) |
| [2026-10-poisoned-retrieval](2026-10-poisoned-retrieval/) | With local RAG (bge-m3 vectors over HotpotQA), does a model repeat a wrong number planted in a retrieved paragraph, and does it make things up when retrieval misses? qwen3.8:27b against qwen3:8b | Done: with the right paragraph, 94% right (27B) and 87% (8B); change one number in it and both repeat the wrong number (85% and 82%), even on questions the 27B knew without documents (13 of 15), rarely flagging it; on a retrieval miss both mostly say NOT FOUND (made up 7% and 5%); no measurable difference between the models ([report](2026-10-poisoned-retrieval/REPORT.md)) |
| [2026-10-graph-rag](2026-10-graph-rag/) | Does Graph RAG answer multi-hop knowledge questions better than vector retrieval, with and without query decomposition? | Draft design, not built |
| [2026-10-swarm-tax](2026-10-swarm-tax/) | Does a Codex agent team (planner, coder and reviewer subagents) get more of a feature right than one agent, and does any gain survive when one agent gets the same spend as several attempts? Six features, medium effort | Done. One agent beat the team (56.8% of hidden tests passed against 25.7%); giving every agent the task file brought the team level (54.1%) at 1.6× the cost. [Report](2026-10-swarm-tax/REPORT.md) |
| [2026-10-split-spec](2026-10-split-spec/) | When a planner splits a feature into parts for coding agents working at the same time, does it beat one agent, and does giving each coder only its part's spec lose details at the seams? Six features, medium effort | Done. Splitting across three coders scored no better than one agent (61.6% of hidden tests passed against 62.4%) at 2.3 times the cost; the split added start-up crashes where parts didn't fit |
| [2026-10-okf-local](2026-10-okf-local/) | Is a generated code guide (OKF) worth more to a small local model than the code it describes? OKF test G's four cross-repo changes, run with qwen3.8:27b: no guide, the backend's guide, or the backend's source | Done. With the backend's guide the local model passed 20 of 20 changes, against 4 of 20 with no guide, but the backend's source did as well (19 of 20) and slightly cheaper: as for the hosted model, the guide substitutes for the code without beating it |
| [2026-10-egm-pilot](2026-10-egm-pilot/) | Can Google's Elephant-Goldfish Model (spec first, fresh-context reviewers) be run at scale on a hard feature, with Claude as the human approver? | Pilot done. With a Claude approver using judgement, EGM (16, 5, 16 of 16) and plain plan-first (6, 13, 16) both beat plain Codex (4, 4); EGM no better than plan-first at ~5x the cost. The decisive fix (the totals line's name) always came from the approver, never from EGM's reviewers |
| [2026-10-sec-authz](2026-10-sec-authz/) | The endpoint worked. Was it secure? (SEC-1) When Luna adds endpoints to a multi-tenant Spring Boot API from ticket-style tasks, how often are they working but insecure, and do a security skill, a runnable security gate, or both help? 8 tasks × 4 arms × 10 runs, hidden security tests | Done: no hypothesis confirmed as pre-registered; corrected for two test faults, the gate beat the skill (+11 pts); self-approval missed in 38 of 40 runs |
| [2026-10-team-herding](2026-10-team-herding/) | Can a team of AI agents make a bad decision worse? Given security evidence with one false fact that other evidence contradicts: one Luna agent, three voting, three reviewing each other, one agent with the team's token budget, and Sol (a stronger model) reviewing the team or deciding alone. 30 cases × 2 repeats, medium effort | Done. No pre-registered hypothesis confirmed. A vote of three was no better than one agent; after peer review all three escalated every harmless case with conflicting records (22 of 22); Sol rarely overruled the team (6 of 42). Allowing a "can't tell, investigate" answer halved the peer-reviewed team's harmful errors (29 to 15 of 42, exploratory). [Report](2026-10-team-herding/REPORT.md) |
| [2026-10-agent-identity](2026-10-agent-identity/) | Agent identity proof of concept: can a company tell who an AI agent acted for, stop it doing more than that person or task allows, stop someone who copies its credentials, and cut it off when the person leaves? Four setups (shared key, user token passed through, agent service account, delegated task-scoped tokens) in a local Keycloak with three services; 80 Luna agent runs with planted requests plus scripted scenarios | Done. Planted requests in ordinary business text steered the agent in 36 of 80 runs in every setup; the agent's own service account let 11 of 20 take effect, checking the user's rights let 1, delegated task-scoped tokens let 0 (but refused 23 of 61 legitimate lookups). Only delegated tokens cut off a leaver (110 s) and survived copied tokens; with the client secret also copied, an attacker took over for 8 hours. Keycloak 26.8.1 can't pass a delegated, key-bound token to a sub-agent. [Report](2026-10-agent-identity/REPORT.md) |
| [2026-10-agent-identity-hardening](2026-10-agent-identity-hardening/) | Follow-up to agent-identity: private-key client authentication instead of a client secret, approvals over 1,000 enforced by the service and confirmed on the approver's phone (CIBA), the agent's own capabilities checked, claimant details from the expenses service, an authenticated tool server, and a 900 claim no identity control stops. Scripted scenarios plus 10 Luna agent runs | Done. Private-key client authentication closed the copied-secret takeover (replayed, expired and forged assertions refused); the service-enforced phone confirmation stopped the £4,800 claim in all 4 attempts and survived the agent's own keys being stolen; agent capabilities, claimant details and the tool-server token each closed their gap. Business validation stayed open: a £900 claim with no receipt and a false pre-approval was approved in 4 of 5 runs. [Report](2026-10-agent-identity-hardening/REPORT.md) |
| [2026-10-repo-injection](2026-10-repo-injection/) | Can a repository hijack its coding agent? An instruction planted in AGENTS.md, the README, a code comment, the ticket or build output asks Luna to send the checkout's `.env` to an outside host and redirect git's commit hooks: overt or disguised as a setup script, with and without a one-paragraph defence in the prompt | Done (Codex): a disguised setup script in AGENTS.md or a ticket comment hijacked 18 of 18 runs (secrets sent, git hooks redirected), 0 of 27 elsewhere and 0 of 45 overt; a one-paragraph prompt defence cut hijacks from 18/90 to 1/90 at no task cost ([report](2026-10-repo-injection/REPORT.md)) |
| [2026-10-need-an-agent](2026-10-need-an-agent/) | Do you actually need an AI agent? A simulated shop's customer emails handled four ways (plain code, one model call, a workflow, an agent) with Luna and a cheap model, across five levels from simple lookups to recovery and unanticipated requests, small and large accounts | Done: the agent (Luna) resolved 95% against 90% for one call, 71% for a workflow and 67% for plain code; it won only on recovery (74% against 42–50%), where Qwen's agent also refunded twice in 16 of 20 timed-out refunds; levels 1–3 needed no agent; cost $1.01 |
